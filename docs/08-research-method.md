# 核验方法与实际限制

资料截点为2026-10-20，北京时间。仓库中的`checked_on`表示本次研究日期，不等于作品首发日期。

## 实际做过的检查

1. 打开用户最初提供的四个页面。直接读取B站和知乎遇到限制后，使用浏览器读到原页正文；网站专题则读取主页和内部页。
2. 对两条重点B站视频查询公开元数据，并取720P画面作前后段抽帧观察。没有把抽帧称作完整观看或逐字听写。
3. 对补充视频查询标题、UP主、发布时间、时长和简介。未完整观看的条目保留`api_metadata_only`。
4. 从原作者动态复核三视图、服装差分与Codex署名说明。Pixiv作品页本次读取受限，其页码和原图信息采用固定上游目录，保留这个证据层级。
5. 核对用户补充的两个GitHub仓库，同时检查相关数据仓和许可清楚的独立立绘项目。保存其Git树SHA，避免以后把变化后的文件列表当成本次快照。
6. 对本地收录图片核对SHA-256，部分另与上游Git blob核对。预览、截帧、作者原图及独立项目图分开登记。
   目视检查中发现上游一张Gemini变体误分类；依据原图多处SEED标记和豆包玩偶纠正归属，保留原记录，不修改原图。
7. 发布前运行本库校验脚本；发布后核对远程可见性和Git树，结果另附交付记录。

## 证据层级

| 字段 | 本次意味着什么 |
| --- | --- |
| `api_metadata_and_sampled_frames` | 公开元数据+部分画面观察，不是完整视听审核 |
| `api_metadata_only` | 标题、作者、时间、简介和时长，不补写剧情 |
| `browser_visible_answers` | 页面可见的人类回答；未展开/未加载内容不计 |
| `primary_post` | 读取原作者发布文字；不自动代表验证全部附件 |
| `pinned_repository` | 固定仓库快照的文档与文件结构 |
| `pinned_repository_metadata` | 结构化字段来源；字段内容仍需作者证据支持 |
| `curator_metadata_only` | 从整理站目录取得，未逐项确认作者和许可 |
| `upstream_reported` | 本次无法直接核对，明确依赖上游记录 |
| `official_product_reference` | 仅确认官方产品入口，不确认存在官方娘化 |
| `access_limited` | 本次入口读取受限，不声称已读到内容 |

来源表是入口注册表；具体结论仍应看角色页、重点来源笔记和逐文件记录。HTTP 200只代表页面返回，不能证明里面每一句话都正确。

## 数据统计怎样读

lmy414的作品数为固定`works.json`中的记录数；不是逐图检查后的唯一原作数。角色出现次数允许一件作品归多个角色。图片仓文件数包含原图、派生图和预览，不能直接当作品数。授权字段为空保持`unrecorded`，不在统计中替换成已授权。

本库38个覆盖条目中包含模型家族、产品、平台、编程工具和历史产品；待补条目不是已完成的角色。17个文字档案不等于17套本地完整美术包，详细状态分别保留。

《大AI和小AI们》的北京时间日期采用公开API结果，而不是聚合主页的日期概括。上游收集进度为历史快照；后续作者动态已有的三视图另列新入口。模型梗保留作品语境，不跟随标题升级为当前事实。Sora原产品入口转到官方停用说明，因此只作为历史档案候选。
