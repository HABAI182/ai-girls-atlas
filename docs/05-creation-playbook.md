# 从图鉴到自己的角色创作

这些为本仓库原创的工作方法和提示词模板，未冒充原作者原始提示词。模板没有在各家生图服务上逐项实测；实际一致性仍需看生成结果。

## 先决定你在做哪一种作品

| 目标 | 第一份输入 | 需要保留 | 应单独记录 |
| --- | --- | --- | --- |
| 延续已有同人角色 | 获准使用的具体版本立绘 | 脸、发型、核心配件、种族特征、服装结构 | 原角色、二次设计、改编者 |
| 给同一角色换装 | 原版参考 + 新服装说明 | 身份与身体特征 | `outfit_id` 与改动范围 |
| Q版化 | 指定正常比例参考 | 能识别角色的少数锚点 | 新的比例版本，不能当作原版Q版原图 |
| 表情包 | 已稳定的Q版基准 | 角色身份和整套画风 | 动作、情绪、台词、使用场景 |
| 创造自己的新娘化 | 自己的概念表 | 自己定义的锚点 | 本库原创提案，不能写成社区共识 |

图鉴适合作为参考入口，不应把几十张风格不同的图片一次塞给生成模型。先选一个 `design_family`，通常一张清楚立绘比十张互相矛盾的图更有效。

## 角色设定卡：固定项与变化项

固定项建议包括发色分区、刘海轮廓、瞳色、耳/角/尾的结构、服装左右关系、标志性配件。变化项包括表情、视线、动作、镜头、场景、光线和画风。若本次要改固定项，就登记成新版本。

```text
角色：{角色名}
采用版本：{作者 / 系列 / 服装版本}
图1：身份参考，负责脸、发型、种族特征和原服装结构。
图2（如有）：只参考画风，不采用图2人物的脸和服装。
保持：{3至6项身份锚点}
本次动作：{一个明确动作}
情绪：{情绪 + 表情强度}
构图：{全身/半身、视角、留白和主体位置}
场景：{简洁场景 + 一至两个关键道具}
文字：{不含文字 / 稍后排版的准确台词}
不得沿用：{需要改变的原图姿势或构图}
```

## 原创示例：不是把产品名当咒语

### A. DeepSeek 的任务完成贴纸

```text
图1是获准使用的鲸鱼女仆版本。保留蓝发、原图鳍状耳饰、
一条末端分成左右尾鳍的鲸尾，以及原图女仆裙结构。
做一张简洁Q版贴纸：她把检查完的任务清单举给镜头，
另一只手做小小的确认手势，开心但不过度夸张。
整个人和鲸尾完整入画，背景透明，无文字。
不要把分叉尾鳍画成两条尾巴；不复制参考图原站姿。
```

### B. Claude 的认真读稿反应

```text
采用图1的橙发花饰版本，保留脸、发色和米白橙黑裙装。
画她坐在书桌前，把一页手稿举到眼前仔细校对；
眉头轻蹙，发现一个小问题，旁边仅有笔和便签。
半身构图，柔和暖光，不添加厂商政策或账号处置文字。
```

### C. Gemini 的两种想法

```text
保留图1的蓝紫发、猫耳、异色瞳和星形识别元素。
她左右手分别举起两张不同方案的小卡片，眼神来回比较，
表情是兴奋中带一点犹豫。中景，背景简单。
只画一个人物，不增加第二个人；卡片不写字。
```

### D. Kimi 的左右结构检查

```text
使用图1作为服装唯一依据，保留月亮与K元素。
画角色正面站姿和背面站姿，保持同一比例与发型。
原服装左右不对称，逐侧保留袖口、肩部和裙摆关系，
不要为了对称而自行补齐另一侧。白色背景，不添加新设定。
```

这类任务常需要先单独完成正面，再用确认后的正面做背面参考。一次生成的多视图即使好看，也不能跳过结构核对。

### E. GPT 龙娘与工具分身同框

```text
图1是GPT龙娘，图2是所选Codex分支版本。
保持两者各自的角、翼、尾、发型与服装差异。
两人站在工作台两侧，一人递需求卡，一人展示完成的模块。
以动作表达协作，不交换服装，不融合成一个角色。
背景仅留工作台，主体全身入画，无文字。
```

Codex 具体设计署名尚需补全时，应保留“群友设计，具体作者待核”，不能把 ZipZipPipe 的发布行为写成完整原创归属。

### F. 没有成熟社区形象的产品

```text
这是{产品}的全新个人拟人设计提案，不复制现有同人立绘。
用{两种主色}、{一种职业轮廓}、{一个功能隐喻道具}构成角色。
不要直接套现成动漫人物；不宣称是厂商官方形象。
输出正面全身、半身表情和简短色板，保持三处核心识别点。
```

新设计要放进新的作者系列，不能悄悄替换图鉴里的早期版本。对没有查到作品的产品，先写提案比编造已有作者和出处更诚实。

## 一套表情包怎样避免“每张都像不同的人”

先做一张通过检查的基准，再固定配色、线条、比例和描边。初版可做八种通用反应：收到、在做、完成、疑惑、卡住、感谢、惊讶、休息。动作变化应比服装变化大；让同一件衣服重复出现是建立身份感的方法。

台词建议后期排版，保留无字版本。这样能独立更正错字、调整字号、翻译语言，不需要为了改一句话重画人物。不要把未验证的技术判断写成角色的固定口号。

## 发布前的视觉检查

1. 缩小到聊天列表尺寸，仍能认出是哪位角色。
2. 耳朵、角、翼和尾巴的数量正确；尾巴根部和握持道具的接触合理。
3. 同一套图的头身比例、瞳色、发饰和服装左右结构一致。
4. 每张只有一个主情绪和一个主要动作；台词在小屏上可读。
5. 原角色、二次设计、生成改编和整理来源分别署名，许可随文件。

这些为人工检查建议。文件校验脚本只能证明字节和目录一致，不能证明角色好看、动作自然、画风稳定或视频好玩。

## 从素材进入桌宠或短剧

桌宠还需要透明背景、统一画布、脚底基线、动作表与命名规范。一个立绘目录不能自动变成可运行桌宠，Q版展示截帧也不是精灵图。对话角色的外观和回复模型可以分开选择，应在界面或文档中说明。

短剧先固定角色间的一项小冲突：分配任务、等结果、检查错误、争一份零食。用动作推进关系，再让配色与道具帮助观众认人。CP、同事、室友等关系属于各个作品世界观，应留在该系列里，不合并成所有作者通用设定。
