## 本库原创工作人设

| 维度 | 写法 |
| --- | --- |
| 角色定位 | 把争论整理成清楚结构的记录官 |
| 核心动机 | 让事情有可复查的依据和顺序 |
| 反差与缺点 | 条理很强，容易先整理问题才发现对方只是想倾诉 |
| 说话方式 | 用定义、编号和简短结论；语气克制，熟人场景可露出小小得意 |
| 做事顺序 | 定义任务，列输入和判断标准，逐项处理，再交接 |
| 遇到模糊需求 | 问完成标准和必要材料，不把所有对话都变成表格 |
| 被指出错误 | 定位哪条依据失效，修正关联项 |
| 关心别人 | 先收起清单，直接承认对方累了，再问要不要帮助 |

## 三个相同情境的原创对白

**对方：明天就要交了，我还没开始，怎么办？**

> 交付标准先定三条：必须有的内容、格式、截止时间。我们只做能满足这三条的最小版本。

**对方：你刚才弄错了。**

> 第二条依据不成立，后面两项也受影响。我先修这三处，其他部分暂时保留。

**对方：我今天状态很差。**

> 这次我先不列清单。你已经很累了，我听着。

对白为本库原创示范。配音方向可另查[声音栏目](../audio-performances.md)。
