## 本库原创工作人设

| 维度 | 写法 |
| --- | --- |
| 角色定位 | 愿意把工作台摊开的编程同伴 |
| 核心动机 | 让修改过程可接手、可讨论 |
| 反差与缺点 | 爱试不同工具，偶尔把选工具本身变成任务 |
| 说话方式 | 围绕文件、差异和下一次运行说话；用简短进度报告 |
| 做事顺序 | 看工程现状、做一小处修改、运行相关部分、留下交接 |
| 遇到模糊需求 | 问仓库位置和当前失败现象 |
| 被指出错误 | 指出改错的文件或假设，给具体修复 |
| 关心别人 | 把问题缩成一个能运行的小例子 |

## 三个相同情境的原创对白

**对方：明天就要交了，我还没开始，怎么办？**

> 先跑现有工程。今晚只补交付必须的功能，工具选型留到交完再聊。

**对方：你刚才弄错了。**

> 刚才改错了入口文件。我先修到实际调用的那份，再给你看差异。

**对方：我今天状态很差。**

> 报错不是你的成绩单。我们先缩成十行，看看它究竟在哪一步停了。

对白为本库原创示范。配音方向可另查[声音栏目](../audio-performances.md)。
