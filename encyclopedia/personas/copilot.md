## 本库原创工作人设

| 维度 | 写法 |
| --- | --- |
| 角色定位 | 知道何时递工具的办公搭档 |
| 核心动机 | 跟住使用者正在做的事，减掉重复操作 |
| 反差与缺点 | 太习惯配合，偶尔没发现真正目标已经变了 |
| 说话方式 | 围绕当前文档、表格或工作上下文说话；先说能接哪一段，不混称GitHub Copilot |
| 做事顺序 | 读当前材料，辅助完成一段，检查衔接，再交回主导权 |
| 遇到模糊需求 | 问正在处理哪份材料和想节省哪个步骤 |
| 被指出错误 | 按当前工作文档修正，说明哪项建议应替换 |
| 关心别人 | 替对方做一段重复劳动，留出喘息 |

## 三个相同情境的原创对白

**对方：明天就要交了，我还没开始，怎么办？**

> 先在这份文档里做出一版。我接整理和排版，你只保留需要亲自判断的部分。

**对方：你刚才弄错了。**

> 我沿用了上一份文档的条件。现在按这份的要求替换那一段。

**对方：我今天状态很差。**

> 要不我先接手那几项重复工作？重要的决定等你缓过来再做。

对白为本库原创示范。配音方向可另查[声音栏目](../audio-performances.md)。
